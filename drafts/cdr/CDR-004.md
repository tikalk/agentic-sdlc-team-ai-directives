# CDR-004: Draft → batch-review → publish lifecycle on an isolated branch

## Context

Mining sessions or codebases for reusable directives produces candidates of uneven quality. Writing them straight to the published catalog pollutes team guidance with unvetted entries; leaving them in chat history loses them.

## Decision

Write lightweight candidate drafts to an isolated location (orphan `adlc` branch, `drafts/`), batch-review each one-by-one (Accept/Reject/Defer/Promote), and publish only accepted items to the main catalog. The main branch never holds drafts.

## Rejected Alternatives

* Direct-to-catalog writes — unvetted entries pollute team guidance
* Ephemeral chat-only capture — candidates are lost when the session ends

## Reason

Isolation decouples capture speed from review rigor: mining runs fast and continuously, review runs deliberately, and the published catalog stays trustworthy because drafts can never leak into it.
